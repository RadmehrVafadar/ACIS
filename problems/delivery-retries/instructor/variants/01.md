# Dispatch replay debrief

The starter deduplicates the scan row but updates the parcel's current facility on every delivery.
An old retry therefore rewinds the shipment even though the event log has no new entry.
It also accepts an existing ID paired with a changed facility.

Look up a scanner event in the parcel's namespace and compare the stored facility with the incoming one.
Return the original event for an exact retry and HTTP 409 for a conflicting payload.
Update the parcel summary only when a fresh event is accepted.
Keeping the lookup and summary update in the same transaction under the parcel lock preserves that contract across concurrent requests.

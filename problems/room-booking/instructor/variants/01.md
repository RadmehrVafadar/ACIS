# Investigating the calendar lookup

The faulty availability query checks whether an existing meeting starts between the two requested times.
That overlooks a meeting already in progress and includes one beginning exactly at the requested end.

For half-open intervals, a conflict exists when the existing start precedes the proposed end and the existing end follows the proposed start.
Keep the query scoped to the selected room.
The transaction locks that room row before checking conflicts, which serializes competing requests even while the calendar is empty.

The four checks cover touching endpoints, several kinds of overlap, room isolation and invalid durations, and competing requests for a single slot.

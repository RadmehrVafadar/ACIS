# Publishing request, save, and response

The creation view passes an undefined name into the serializer, so valid requests return HTTP 500 before validation.
Read the body from `request.data`, call `is_valid`, then persist the validated post with the authenticated author using `save(author=author)`.
The starter constructs an unsaved model and returns only a message.
Serialize the saved row as `post` in the HTTP 201 response.
For an omitted or empty excerpt, fill it from the first 150 content characters in the input serializer.

The first test checks the public response and populated author.
The second reads the actual database and the subsequent My Posts listing.
The browser fills an empty excerpt itself, so an API request without it provides an extra check.
